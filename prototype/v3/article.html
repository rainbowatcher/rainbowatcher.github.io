数据仓库、数据湖、湖仓一体以及他们的区别

三个概念放在一起时，差别主要在存什么、给谁用，以及改动一条数据要付多少代价。

2022-06-25 Data WarehouseDataLakeLakeHouse

数据仓库是什么 #

首先我们复习一下什么是大数据的 4V 特性。

大数据的 4V 特性：数据量极大、数据增长快、数据种类多、价值密度低。

大数据的定义其实很模糊，它并没有说明它所谓大的边界在哪里。广义上的大数据指的是围绕 Hadoop 的大数据组件生态圈，由 HDFS 提供分布式文件存储能力、Yarn 提供资源调度能力、MapReduce 提供大规模计算能力。在具备了这些能力之后，大数据便有了实现的可能。

Hadoop 诞生之后陆陆续续又出现了很多优秀的开源项目：Zookeeper 提供集群高可用能力，Hive 提供使用 SQL 读写 HDFS 文件的能力，HBase 提供在 HDFS 上构建非关系型数据库的能力。有了这些，才能在 HDFS 上方便地构建数据仓库。

数据仓库定义了四大特征，理解这四条，基本就能判断一个系统是不是数仓：

  • 面向主题：可以高效分析关于特定主题或职能领域（例如销售）的数据。
  • 集成：在不同来源、不同数据类型之间建立一致性。
  • 相对稳定：进入数据仓库后，数据将保持稳定，不会发生改变。
  • 反映历史变化：分析着眼于反映历史变化。

一个精心设计的数据仓库支持高速查询、高数据吞吐量，能够凭借出色的灵活性帮助用户细分数据或降低数据量，进而执行更加细致的数据检查，满足高层级和精细化数据管理等各种需求。同时，它还能为中间件 BI 环境提供一个坚实的功能性基础。

数据湖是什么 #

数据湖就是原始数据保存区。虽然这个概念国内谈得少，但绝大部分互联网公司都已经有了。国内一般把整个 HDFS 叫做数据仓库（广义），即存放所有数据的地方，而国外一般叫数据湖（data lake）。

两者的命名差异不是文字游戏：叫「仓库」时，隐含的是数据已经按主题整理过；叫「湖」时，隐含的是先把原始形态接进来，之后再决定怎么用。数据湖多基于 HDFS、对象存储这类架构，对节点配置要求不高，原生支持分布式部署，能自适应扩容，也能存放任意类型的数据。

他们的异同 #

数仓是一个比较早的概念，出现在大数据技术成熟之前，所以数仓多指关系型数据库中搭建的数据仓库。数据湖是在大数据出现后才有的概念：存储可以放结构化或非结构化数据，随后业界又出现了 MPP（Massively Parallel Processing）架构数据库，于是有了下面这张对照表。

三类存储的对照 #

维度 数据仓库 数据湖 湖仓一体
存储数据类型 适用于结构化数据 适用于半结构化和非结构化数据 可以处理结构化、半结构化和非结构化数据
目的 最适合数据分析和商业智能（BI）用例 适用于机器学习（ML）和人工智能（AI）工作负载 适用于数据分析和机器学习工作负载
成本 存储成本高且耗时 存储具有成本效益、快速且灵活 存储具有成本效益、快速且灵活

由于数据仓库指使用关系型数据库集中存储数据，所以存储数据类型为结构化数据，可以配合 Kettle、PowerBI 等工具实现数据分析、可视化与商业智能应用。像 Oracle、SQL Server 这类关系型数据库对单节点硬件配置要求较高，且对分布式部署支持有限，所以存储与运维成本都很高。

数据湖这边可以搭配 Mahout、QuickSight、SageMaker、Flink ML 等实现对数据的机器学习和预测分析。缺点也很明显：大量松散数据存放在其中，需要有序的管理才能让数据湖不至于变成数据沼泽；各项功能分散在不同组件里，自己搭建会需要巨大的运维成本。

数据湖还缺什么 #

数据湖缺乏一些关键特性：它们不支持事务，不强制数据质量，并且缺乏一致性、隔离性，使得很难混合读写过程，以及批处理和流处理。这几点正是「湖仓一体」想补上的部分：保留低成本的存储，同时把事务与一致性带回来。

读这张表时的一个前提

表格比较的是典型形态，不是某个产品的规格。选型时还要看现有团队更熟悉哪套组件、数据是否已经有稳定的主题模型，以及 BI 与 ML 两类负载谁先落地。

数仓分层 #

分层解决的是数据标准化、数据质量与一致性：原始数据进来之后，逐层收敛到可以复用的主题域，再把报表与指标建立在稳定的中间层上。分层不是越多越好，每多一层就多一份调度、回溯与口径维护的成本。

换一个角度看，分层也是「湖」和「仓」之间最实在的差别：湖允许先存后整理，仓要求先定好模型再写入。踩过的坑大多出现在两者交界处，而不是某一层内部。
