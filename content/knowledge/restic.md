## 要点

- 适用面是「单机到几十台机器的离机备份」：数据在任意 Linux 主机上，加密后增量落到普通存储。
- 快照之间无依赖链，删旧快照是常规维护而不是危险操作；代价是删快照等于删那段历史。
- 多台机器、多个路径写同一个仓库时按内容块去重，这是它与增量链式备份工具最重要的差异。
- 它不解决一致性：数据库要先导出或先做文件系统快照，restic 只看到一条已就绪的数据流。

## 场景

| 场景                | 痛点                           | 形态                                                                  |
| ------------------- | ------------------------------ | --------------------------------------------------------------------- |
| 个人工作站 / 笔记本 | 云盘会把误删同步到全部设备     | 定时推到移动硬盘或对象存储，按时间点捞回单个文件                      |
| 单台 VPS / 小服务器 | 无快照能力，误操作和入侵都致命 | 凌晨备 `/etc`、站点目录，留两周日备加半年月备，定期在空机器上演练恢复 |
| NAS / 家用存储      | RAID 不是备份，勒索会一起镜像  | 加密后推到异地对象存储，作为 3-2-1 里离机的那一份                     |
| 数据库与应用        | 直接拷数据文件是不一致中间态   | 先逻辑导出再进备份，成败以导出命令的退出码为准                        |
| 多机共用一个仓库    | 各机全量备份导致存储翻倍       | 几十台机器写同一仓库，跨机器也去重；代价是共享一个密码                |
| 历史需要分层取舍    | 一年前的日备无价值但不敢删     | 按天 / 周 / 月分层保留，删旧快照后回收空间                            |
| 异地第二副本与迁移  | 换供应商或机房租约到期         | 两个仓库增量互相同步，过渡期双写                                      |
| 受限环境            | 不能装服务端、只有普通用户权限 | 单二进制无服务端，能跑在共享主机、容器旁车、对象存储桶上              |
| 防篡改              | 攻击者拿到凭证会主动删备份     | 仓库权限与生产机隔离，存储端只追加                                    |
| 合规留存            | 需证明历史数据未被修改         | 完整性校验配合不可变存储；反向义务是丢密钥即数据不可用                |

## 与相邻选项的区别

| 选项             | 分界                                                                       |
| ---------------- | -------------------------------------------------------------------------- |
| rsync            | 只保当前状态，不保历史、不加密、不去重                                     |
| ZFS / Btrfs 快照 | 防误删，防不住硬盘坏与整机丢失，属于本地那一层                             |
| borg             | 能力接近；borg 偏向单机自建仓库，restic 胜在无服务端、后端多、多机共用仓库 |
| 云厂商备份服务   | 省心但绑定厂商；restic 可跨云、可落地到自有存储                            |
| 逻辑备份脚本     | 脚本给的是某一次导出，restic 在其上补历史、增量与加密                      |

## 边界

- **不适合秒级 RPO**：单机扫描与上传受带宽限制，核心在线库要用专用方案。
- **不适合文件系统一致性要求高的库**：应先有 LVM / ZFS / VSS 快照，否则备份的是撕裂状态。
- **密码丢即数据丢**：没有找回途径，密码要和仓库分开存放并纳入其他备份。
- **去重收益取决于数据形态**：加密容器、压缩包、虚拟机磁盘几乎不省空间。
- **跨版本共用仓库有风险**：老客户端读不了新格式的块，升级要所有客户端一起。
- **单仓库是单点故障**：没有第二副本时，仓库所在存储的丢失等于备份全丢。
